# 队列跨批次存续，批次短暂且独占一个目录

队列是用户长期维护的对象，批次只是它的一次执行。因此「完成」必须记在队列条目上（连同该曲目的批次目录），而不是靠「找得到旧产物」推断；每次执行批次时新建一个时间戳目录，绝不复用**他批**的目录。

**唯一例外**：**失败曲目重试时回到它自己记录的批次目录**。复用的是「这个曲目自己的目录」，不是「别的批次的目录」——同名串音的前提是「同一个目录里出现了两个不同来源的同名文件」，而重试跑的就是当初那一个曲目，前提不成立。允许这条例外，是因为分离是整条流水线里最贵的一步，重跑转写却要重算分离属于纯粹浪费。

**考虑过的替代**：让批次目录固定、靠复用已有人声轨省下分离开销。否决理由：只要目录复用，`同名但不同来源` 的曲目就会读到别人的产物，而现有代码在这种命中下只打一行日志、不报警（`src/vocal2midi/core/separation.py:87-91`）；同一个歌名出现在两张专辑里是常态，把静默错误源留在批量里不可接受。

**注意**：新建批次目录只解决了**跨批次**的同名冲突，没有解决**同批次内**的同名冲突——「同一首歌的两个版本」完全可能一起进队列。因此批次内的产物主名必须在首次进批时确定并记在曲目上（重名追加序号），不能每首现算。

**代价**：批次之间不共享人声轨。重试失败曲目时，若它上次连人声都没分离出来，就得重新分离；这是用「每次都正确」换「偶尔多算一次」。
