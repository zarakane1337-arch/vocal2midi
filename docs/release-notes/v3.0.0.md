## [3.0.0] - 2026-10-21

**摘要：从「一次一首」变成「一次一批」。首屏的单文件输入框换成队列：多选导入、
多文件拖入、上移下移、清空，每首单独记录状态与产物，整批跑完给出成功 / 失败与原因；
队列跨重启存续，再点「开始转换」只处理待转换与失败的。重试只跑失败那一首并复用已有
人声轨，整个批次复用一个 `Separator`。分离层接上分段回调，取消不必再等整首跑完。
输出改为 `<时间戳>` 批次子目录，同批重名不再互相覆盖；同时补上 pytest 测试地基与
两份 ADR。**

### 新增

- **批量转换**：一次可以排入多首歌曲，让它们自己跑完。界面首屏从单文件输入框换成了
  队列列表：支持多选导入、多文件拖入、删除、清空、上移下移，以及一键「打开批次目录」
  （优先打开选中曲目的目录，没选中时回退到队列里最近一个批次）。
- **队列跨重启存续**：队列本身、顺序、每首的状态与产物位置都写进 `settings.json`；
  已完成的曲目重启后不会重跑，再点一次「开始转换」只处理待转换与失败的。
- **整体进度**：进度条按「已完成曲目数 + 当前曲目内部进度」推进，并显示
  `第 3/8 首 · 分离中` 这样的文字；整批结束给出成功 / 失败与失败原因的汇总。
- **失败不中断**：某一首出异常只会把它自己标成失败并带着原因，剩下的照跑；
  「查看失败原因」直接读记录下来的原因，不再去找一个不存在的产物。
- **测试地基**：`tests/` 下 4 个文件、94 个用例，覆盖队列状态机、批次编排、
  流水线阶段与分离层纯逻辑。测试**不需要 torch / demucs / 权重**：分离层用
  `FakeTensor` / `FakeSeparator` 顶替，`conftest.py` 只替换 `tmp_path` 以适配
  仅允许 `0o755` 目录的环境。开发依赖见 `requirements-dev.txt`，`pytest.ini` 固定测试路径。
- **领域文档**：`GLOSSARY.md` 统一「曲目 / 批次 / 队列 / 阶段」等术语；
  `docs/adr/0001-queue-outlives-batch.md` 与
  `docs/adr/0002-serial-batch-with-one-separator.md` 记录「队列比批次活得久」
  「串行批次共用一个 Separator」两个决定及其代价。

### 变更

- **输出目录结构**：每次「开始转换」在输出根目录下新建一个 `<时间戳>` 子目录，
  全批产物都落在里面（哪怕只有一首）。以前的产物平铺在 `out/` 下；旧文件不会被
  迁移或删除，但新版本不再往那里写。
- **取消可在分离中途生效**：接上了 demucs 的分段回调，取消不再等整首跑完；
  被打断的那一首退回「待转换」（不是失败，也不弹错误框），已完成的保持不动。
- **重试复用已有人声轨**：失败曲目重跑时回到它自己那个批次目录，人声轨还在就只重跑转写，
  分离是整条流水线里最贵的一步。
- **模型只加载一次**：整个批次复用一个 `Separator`，不再每首歌重载四份 `htdemucs_ft` 权重。
- **阶段边界集中定义**：进度权重收敛到 `pipeline.STAGE_WEIGHTS`，写盘阶段也真正出现在
  进度与阶段文案里；产物命名收敛到 `core.names`，不再三处各拼一遍。
- **仓库整理**：`.gitignore` 重排为六节，去掉从未生效的 `pip-*/` 与 `plugins/` 规则；
  清掉探针残留、过期构建物与编辑器锁文件。

### 移除

- 主窗口的单文件输入框与「最近」菜单（曲目直接从队列里选）。

### 修复

- 同一批次里两首同名歌曲不再互相覆盖产物：后一首的产物主名追加序号，两份都保留。
- 「完成」不再只靠找旧产物推断：状态记在队列条目上，产物被删时启动或开跑前会降级为待转换。
- 进程被杀后不再留下永远「转换中」的曲目：启动时把落盘的 `running` 恢复为待转换。
- 拖入不支持的文件不再静默吞掉，给出拒绝原因。
- 整批汇总带上失败原因；取消时状态文字不再重复「已取消」。

### 升级注意

- 主界面不再有单文件输入框，转换统一从队列发起（单首也是排进队列再开始）。
- 产物改为落到 `out/<时间戳>/`；旧的 `out/*.mid` 不迁移、不删除，也不会被新版本重写。
- 队列存在 `%APPDATA%\vocal2midi\settings.json` 里，删掉该文件等于清空队列（音频文件本身不动）。
